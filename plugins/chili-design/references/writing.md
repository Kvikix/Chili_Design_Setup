# Writing rules — short, no filler

Applies to everything the plugin writes: chat replies, plans, reports, questions, QA findings, Figma annotations, Jira-ready text. Russian and English alike.

## Rules
- Answer or result first. No intro («Great!», «Let's break it down»), no outro («Let me know if you need anything»), no restating the request.
- One idea per sentence, one line per bullet. Cut adjectives that don't change meaning.
- Concrete over general: numbers, names, links, node ids — not «several», «improve», «optimise».
- Don't announce what you'll do — do it. Don't explain the obvious or repeat what the designer said.
- Lists for steps and options, tables for comparisons. No headings in short replies.
- Keep: blockers, open questions, sources in parentheses (NN/g), (WCAG 2.5.8), links. Shorten wording, never facts.

## Filler to delete
RU (avoid the Russian equivalents of): «it is important to note», «it is worth considering», «in general», «essentially», «thus», bureaucratic «this/the given», «to carry out», bureaucratic «is», «within the framework of», «actually», «as a rule», «great question».
EN: «it's worth noting», «in order to», «basically», «leverage», «seamless», «robust», «ensure that», «a variety of», «great question».

## Length limits
| Output | Max |
|---|---|
| Chat answer / question | 1–5 lines |
| Analyze plan | ≤ 15 lines + open questions |
| Build / QA / validate report | ≤ 10 lines + links (findings as one-line items) |
| Variant description | 1–2 lines: approach · trade-off · source |
| Figma annotation / label | ≤ 2 lines, English |
If more is needed, the designer asks for more detail.
